COPY-ON-WRITE / VERIFIED-OBJECT LOCK
A verified legal/source object is never silently overwritten.

MULTI-WORKER COLLISION RULE
Workers may research/compute in parallel against a stable BASE_GENERATION.
Completion order need not equal start order.
Before commit, compare the work unit’s dependencies against current generation.
If no relied-upon dependency changed, the independent unit may commit.
If a relied-upon object changed, mark CONFLICT and revalidate only the affected dependency/unit; do not reload or rebuild the whole corpus.
One project cannot seize, rename, or overwrite another project’s namespace, cursor, work unit, or local master.


DIRTY-SET RECOVERY
Recovery starts from unresolved states, not a full rescan:
DIRTY; COMMITTED-but-not-VERIFIED; CONFLICT; ACQUISITION-BLOCKED.
CLEAN/VERIFIED unchanged objects are not recomputed or re-fetched absent a demonstrated verification/version/source gap.
FAST CACHE FIRST; exact IDs first; dependency fingerprints before recomputation.
