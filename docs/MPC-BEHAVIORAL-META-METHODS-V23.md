# MPC V23 — Behavioral / Sales / Nudge Science of Methods on Methods

**Source:** \`mjcustomcomputers-dotcom/Machine-Bug-Tool\` stacked on V22 PR #22 at \`fa36798a6c61bd8953a0d77e2eea202b82f8ea77\`. **Branch:** \`feature/mpc-behavioral-meta-methods-v23\` (**draft PR; not deployed or merged**).

## Objective: method-of-method, not a bag of influence tactics

MPC’s existing SOURCE → ATOM → METHOD → PROCESS → INVERSE → FALSIFIER → DECISION architecture is preserved. V23 introduces **16 sourced, review-only behavioral/consumer-protection/sales/metascience method contracts**, plus finite local structural planners and negative controls. It does **not** add registered MHA/MHC/BL identities, does not modify the 239 candidate Atlas or 24 executable native methods, does not deploy new Site tools, and does not magically turn a behavioral framework into a measured causal effect. Psychological persuasion work is classified in terms of **voluntary informed choice, seller/buyer fit, and consumer harm**, never covert targeting or inference of personality/mental health from sparse observations.

An original publicly known methodology retains its author and usage terms. Source linkage is not proof the entire paper was replicated, and a method name or marketing claim is not a validation score. Huthwaite SPIN documentation describes a proprietary commercial method and may make vendor-originated effectiveness claims; V23 records the source without promoting those claims as independent evidence.

## Method-science grammar: five distinct levels

1. **Native ATOM:** one typed, explicitly caller-supplied observation with scope, subject, owner, source ref, source version, and epistemic state. \`OBSERVED\` is not authenticated merely because the caller says so. \`SYNTHETIC\` cannot mix into live record batches. \`CONTRADICTED\` plus supporting states yields \`CONTESTED\`, never an averaged truth. Raw user text, demographic traits, emotional diagnoses, and hidden propensity scores are not inputs to this local planner.
2. **METHOD CONTRACT:** declared prerequisite types, hypothetical output types, the authority/theory source, an adverse falsifier, and an implementation status. A useful theory produces a *candidate experiment*, not a result.
3. **PROCESS / INVERSE:** ask which observation, independently checked assumption or method output is missing; invert dependencies to find the smallest next acquisition/validation step. Rank absent **primary records** by the exact number of structural one-atom unlocks, never invented information-gain probabilities. Keep *method-derived outputs* separate from source records.
4. **METHOD ON METHOD:** pair typed output A with input B. A hypothetical BARRIER_HYPOTHESIS may enable a plan from COM-B to Behaviour Change Wheel to MOST, but it remains hypothetical until independently executed and validated. Challenge the chain for competing explanations, common source owners, false causation, audience rights, and unreported side effects. No recursive fan-out or automatic model execution occurs.
5. **METAMETHOD AUDIT:** use V22 finite pairwise covering design + independent replay, autonomy/disclosure observations, explicit harms/welfare outcomes, assignment/stopping/multiplicity controls, and a TIDieR-style replication checklist. The code tests **structural preparedness**, not statistical significance or real-world efficacy.

## Examples of truly different methods working on each other

**COM-B × Fogg × Method falsification:** A customer misses an optional setup action. An unsupported sales assumption says “low motivation.” COM-B forces separate capability/opportunity/motivation observations; Fogg asks about ability and prompt timing. If setup instructions or access were missing, calling this a motivation problem fails. Run **observation acquisition first**, not persuasion.

**SPIN → Jobs-to-Be-Done → adaptive selling:** A consented conversation records situation, problem, implications and desired payoff. A JTBD candidate describes the progress the buyer actually wants. Adaptive selling checks declared solution capability against buyer-stated constraints. Reverse-check: if the proposed feature does not address the stated job, stop and ask for an independent requirements record; do not invent urgency or psychological weaknesses.

**Choice architecture → autonomy audit → dark-pattern falsifier:** Compare accept versus decline path steps, whether consent was preselected, whether full price appeared before commitment, truth/scarcity evidence and cancellation/reversibility. Signals cause **review**, not an accusation or law-violation finding. Alternative explanations and actual full UI/offer terms must be collected. Never optimize designs to make refusal harder.

**BCT / Behaviour Change Wheel → MOST → TIDieR → sequential inference:** Define an intervention’s mechanism, independently varied components, budget and harms constraints; use V22 pairwise coverage to plan **test combinations**, not power. Define assignment, primary outcome, consumer welfare/harms, stopping rule, multiplicity, delivery fidelity and version. A fixed-name intervention with changed delivery is not automatically comparable. Outcome deltas do not prove causality without appropriate execution and analysis.

**Adversarial *method vs method*:** Find cases where the same observation is used to justify several methods: a shared customer conversation is one source, not three independent confirmations. Require independent controls, alternate models and source-version-sensitive replays. Convert unresolved facts into targeted acquisition actions rather than resetting to architecture mode.

## Local implementation

\`lib/behavioral-meta-methods-v23.mjs\` exports:

- \`reviewBehavioralAtoms\` — source-bound typed atom applicability, source/derived-output distinction, evidence-state and autonomy gates
- \`planBehavioralEvidenceAcquisition\` — deterministic, finite one-atom structural-unlock ranking for **primary record acquisition only**
- \`planBehavioralMethodInteractions\` — output-to-input research contract graph with missing prerequisites, nonindependence warnings, and ethical design lock
- \`auditChoiceArchitecture\` — bounded transparent dark-pattern **signals** from caller-entered interface fields (no OCR, legal judgment or remote site control)
- \`auditBehavioralExperimentProtocol\` — precommitment, assignment, harm, welfare, stopping and multiple-test design checks (not experimental inference)
- \`planBehavioralInteractionControls\` — exact reuse of V22 pairwise test **planning** and independent replay (not completed behavioral experimentation)

The input \`source_commit\` is a 40-character **caller-stated version label**, not cryptographic authentication; source refs and owners also remain unverified until a native connector read supports them. All code is local/deterministic and stores no screenshot text, contact information or psychographic segment. There is no external action connector or automatic data collection.

### Preserved distinction: useful selling vs coercive design

The permitted design intent is declared user benefit or mutual value, with explicit consent, truthful disclosure, clear ability to decline, and no sensitive/covert targeting. Missing safeguards stop an intervention **design** at \`INTERVENTION_DESIGN_BLOCKED\`; read-only audit remains available to identify suspicious patterns. These are product research safety boundaries, not a certification of legal compliance. The safest valid outcome can be **do not nudge**, **simplify an existing task**, **improve information clarity**, or **do not sell when there is no fit**.
