# Controlled atomic method execution

This is an additive execution layer in the existing MPC server. It preserves the original source-owned object, 25 object coordinates, 14 independent jacket axes, 11-field METHOD PACKET, and frozen classifier registries. Input atoms have one typed value, parent/depth, source references, native subject identity, registered classifier references, dependencies, a falsifier and an expected record/custodian. A batch is not a claim that semantic atomization is complete.

## Discover what is actually available

Call `runtime_status`, then `get_universal_contract`. `get_method_ark` supports six `catalog_layer` values. Use `limit` between 1 and 5, and follow the returned `next_offset` until null.

| Layer | Count | What it means |
|---|---:|---|
| IMPLEMENTED | 24 | Executable finite model evaluators |
| METHOD_HOOKS | 10 | Primary-source research and implementation contracts; no standalone checker is claimed |
| FRAMEWORK_OPERATORS | 15 | Original native analytical operators |
| REDUCTION_METHODS | 12 | Original multi-method reduction declarations |
| TRANSFORMATIONS | 17 | Finite supplied-atom operations |
| MIRRORS | 15 | Original native mirror questions |

These inventories overlap in purpose and must not be summed as methods executed. The frozen BL registry remains 32 branches/384 children with fingerprint `7db8a73e32016a8d3df560f649125221615b42a669231ec066ce74fee9d8a58d`. MAXVAR, NESTMAX, MBSS and the separate EXT templates retain their original namespaces and count distinctions.

## Run a controlled comparison

Read `get_universal_contract.atomic_review.input_schema`. `review_atomic_variants` defaults to `PLAN`: it builds the requested finite variations and validates explicit model bindings. Only `mode: EXECUTE_SUPPLIED_MODELS` calls evaluators. Each supplied model names an existing evaluator, supplies its exact input schema and declares JSON-pointer bindings from atom values, dependency arrays or atom presence. Baseline values must match those bindings. Overlapping paths and unsafe object properties reject.

`tests/fixtures/atomic-owner-variation.json` is a complete synthetic example. It starts with a declared native-key match. A controlled owner-value swap updates one explicitly bound operand of the identity model. The equality invariant then fails in the variant. The returned `MODEL_COUNTEREXAMPLE_CANDIDATE` concerns that synthetic model; it is not target evidence or a bounty finding. Original atoms remain intact and every variant is `TEST_ONLY_COUNTERFACTUAL`.

When an installed client has an older tool list, the existing `business_logic_sweep` context accepts `UMTB4:` followed by JSON matching the current routing schema. Its optional `atomic_review` field carries the same input. The routing object ID and atomic object ID must match. No default routing request executes methods automatically. Method Ark layers also work through `method_lookup` in this compatibility path.

## The 17 transformations

REMOVE / ABLATE; RESTORE; SUBSTITUTE; SWAP; INVERT EDGE; REORDER / PERMUTE; PERTURB; MASK / HIDE CHANNEL; PROJECT / REDUCE; EXPAND / RECURSE; COMPOSE; CROSS PRODUCT; STATE DIFFERENCE; INVARIANT TEST; QUALITATIVE SENSITIVITY / LOAD-BEARING TEST; NULL / NO-EDGE TEST; ALTERNATIVE-MODEL SET.

Each operation has a finite supplied-state meaning. Permutation reassigns values among declared compatible coordinate slots; it does not silently reorder a live target history. Projection keeps selected atoms; removing a required model binding blocks that model. Masking creates an unknown value. Expansion requires explicit child atoms and valid parent identity/depth. Restore reads the immutable original even after removal within a composition. Cross products materialize only the requested page. Composition preserves explicit component order and rejects branching components unless alternatives are supplied separately.

A no-change non-control variation stops with `STOP_NO_MATERIAL_INFORMATION_GAIN`. A numerical difference alone does not prove the user's stated semantic reason for splitting. No automatic natural-language atomizer or global minimum decomposition is claimed.

## Four added evaluators

- `propositional_entailment`: finite Boolean truth tables, countermodels and explicit vacuity/inconsistent-assumption status; at most 12 variables and 127 expression nodes.
- `finite_invariant`: BFS on at most 256 supplied states and 512 transitions, shortest reachable violation and separately checked base/step obligations. Unreachable step failures are not reachable counterexamples.
- `abductive_cover`: inclusion-minimal combinations of at most 12 supplied hypotheses under explicitly mandatory effects. Retains alternatives of different sizes; no probability or causal proof.
- `minimal_cut_sets`: inclusion-minimal combinations of at most 12 shared basic events in a 63-node monotone AND/OR structure. No probability or independence assumption.

Primary lineage and precise limits are in each selected method catalog/Ark capsule. The existing 20 evaluator IDs and draft method overlay remain intact.

## Uncommon hooks

The METHOD_HOOKS layer carries linearizability; transaction dependency/isolation; counterexample-guided abstraction refinement; oracle-driven delta debugging; assume-guarantee composition; information-flow hyperproperties; NASA event sequences/common dependencies; incentive compatibility; guarded commutativity with distinguishing continuations; finite epistemic indistinguishability.

Every hook states its required inputs, original source URLs, proposed atom transformations, existing MPC attachment points, falsifiers, implementation route and negative acceptance cases. Hook-to-classifier attachments are proposed structural inferences, not canonical registry membership. Existing narrow evaluators are not relabeled as full implementations of these methods.

## Limits and evidence

Each request admits 64 atoms, 16 transformation declarations, 4 explicit models, 32 invariant checks, and a page of at most 16 variants. Atom states are bounded to 100,000 serialized UTF-8 bytes. A cross product has at most 64 alternatives per declaration. There are at most 512 applied transformation steps and 32 evaluator attempts per request. Oversized individual model receipts retain an explicit executed-but-omitted status, fingerprints and a request to reduce the model or enumeration budget. Missing inputs, unknown values, rejected models and exhausted budgets never become an invariant pass. The transport has a separate response size cap; reduce the atom/model batch or variant page when it reports an oversized response.

Follow both `next_variant_offset` and `next_execution_variant_offset`. The latter points to budget-pending executions even after the variant list ends; `execution_complete` stays false. Use a smaller page and the same base to resume. Use the returned base fingerprint when continuing variant pages. Changing atoms, sources, models or checks invalidates it. Preserve original identities independently of SHA256 receipts. The native MMR identity pattern is not a cryptographic hash algorithm.

All 24 evaluators and all 10 hooks are accounted for with an applicability state. Unknown applicability remains unknown; listing a method is not running it. Reconciliation is explicitly `NOT_PERFORMED_REVIEW_REQUIRED` until the native relation/contradiction/target review is completed. No averaging of method outputs or independent-evidence claim follows from agreement. The original seven reconciliation relations and packet declarations remain in the contract.

The server performs no target traffic, connector dispatch, Drive/Dash persistence, bounty submission or local-device control. Those stages need their actual connectors and destination-specific receipts. The environment runbook explains the existing private plugin connection and the separate local setup boundary.
