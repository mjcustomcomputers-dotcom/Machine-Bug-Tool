# MPC capability review and the final integration standard

Reviewed October 9, 2026, against the connected private GitHub project and its native source/validation artifacts. The installed-repository search for `mjcustomcomputers-dotcom` returned **Machine-Bug-Tool**. This review concerns the accessible repository and its branch history; it does not claim access to every private Codex task, a fresh Drive inventory, or the user's running Windows installation.

## Assessment

MPC contains substantial executable reasoning and evidence-control work. Its strongest supported feature is the combination of acquired-source identity, bounded mathematical methods, independent counterexamples, and retained execution receipts. That provides a sound basis for an advanced research workbench. The evidence does not yet demonstrate general reasoning superiority, automatic invention of validated methods, or a fully integrated Windows product.

The new local-chat update separately adds actual conversation, streaming, selected local models, setup controls, clipboard/text-file input, SQLite retention and a retained launcher. It improves the usable software. It does not retroactively merge every sibling branch or establish model quality from HTTP fixtures.

## Five supported technical strengths

### 1. Decisions can be traced to acquired bytes and actual calculations

The Security Assistant implements `ACQUIRED → ANALYZED → DECIDED`, selects executable JSON arguments from an acquired source by pointer, checks stale source/runtime identity and preserves invalidation history. An outer successful wrapper cannot promote an incomplete nested review. A later reader can inspect which bytes and native calculation supported a disposition. This is an architectural strength; the trace itself does not prove the underlying source claim true. [Controller source](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/297f586a3828c6d50b783fe1fdce766bce5344cd/lib/security-assistant.mjs).

### 2. Independent arithmetic can challenge the retained native answer

The exact numerical review exposes concrete Nash and conservation discrepancies. With `d = 2^-54`, the Nash fixture uses row payoffs `[[1 - 4d, d], [1, -d]]` and column payoffs `[[0, 1], [1, 0]]`. The exact row-action difference is `2d - 6dq`, so indifference requires `q = 1/3`. The original native evaluator returns `0.4`. A strategically irrelevant column translation removes the original floating-point failure while the exact answer remains invariant.

The conservation fixture uses opening `1`, inflow `2^-54`, outflow `1`, closing `0` and tolerance `0`. Its exact residual is `-2^-54`; the original binary64 calculation passes after cancellation. The exact review exposes the failure. [Regression fixtures](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/0f8bc5eec399f729d03e262ee9a90b18c1a825f4/tests/exact-native-numerical-review.test.mjs).

**These passing regression tests preserve known wrong original outputs. They do not mean the original solvers were repaired.** The separate exact adapter preserves the native receipt and binds its comparison to the input. Nash review is limited to 2×2 games. Receiving-build acceptance must exercise this comparison in the actual result/report path and disclose unreviewed scope. [Exact adapter](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/0f8bc5eec399f729d03e262ee9a90b18c1a825f4/lib/exact-native-numerical-review.mjs), [original evaluator](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/0f8bc5eec399f729d03e262ee9a90b18c1a825f4/lib/methods.mjs).

### 3. Information is evaluated by its effect on a permitted decision

The finite information implementation uses exact `BigInt` fractions for weighted utilities and decision comparisons. Its model is a finite single actor/decision with at most 16 states, 16 actions and 16 observations. It distinguishes an actor's observed information from an omniscient simulator, checks that a policy does not secretly depend on hidden state, and requires repeated knowledge to add zero modeled value.

The arithmetic is exact for the supplied binary64 inputs; it cannot recover an intended decimal or establish that a measured probability is correct. In practice, this gives MPC a useful way to rank the next evidence acquisition when probabilities, costs and utility are justified. When those inputs are absent, use an explicit heuristic. [Implementation](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/0f8bc5eec399f729d03e262ee9a90b18c1a825f4/lib/finite-information-reasoning.mjs), [tests](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/0f8bc5eec399f729d03e262ee9a90b18c1a825f4/tests/finite-information-reasoning.test.mjs).

### 4. Method-versus-method experiments have defined independent expectations

The self-play runner compares fault trees with minimal cut sets and Boolean evaluation, accounting with conservation/transfer transformations, event order under distinct contracts, finite abstraction with concrete replay, and bounded planning with exhaustive or analytic checks. The saved V15 evidence includes a 2,560-model graph oracle and 3,215 numerical projections with no recorded mismatches. Fixed experiment families and duplicate suppression make those records inspectable; they do not establish autonomous invention of arbitrary new methods. [Runner](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/0f8bc5eec399f729d03e262ee9a90b18c1a825f4/lib/reasoning-selfplay.mjs), [V15 receipt](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/23d2a69f3b67ef298a3b6c7dab7b2d16fe96a4c0/docs/validation/MPC-REASONING-V15-VALIDATION.json).

### 5. Source, method and delivery states remain distinguishable

The architecture distinguishes catalog consideration, readiness, selected plan, native execution and source authentication. The SQL foundation preserves typed source/classifier references and receipt history. The existing connector layer also gives the host a real dispatch interface. Use those distinctions in the GUI: actual acquired source/version, selected method and its inputs, native result, review disposition, and saved/delivered report must each have the corresponding observation. [SQL foundation](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/e89a059761ae6cea8e08e61a1cfb0bc30b093a86/command-center-build/sql/001-command-center.sql), [host connector contract](https://github.com/mjcustomcomputers-dotcom/Machine-Bug-Tool/blob/0f8bc5eec399f729d03e262ee9a90b18c1a825f4/lib/connector-contract.mts).

## Turn those strengths into a better product

| Area | Required improvement and evidence |
| --- | --- |
| Usability | One working window with a persistent composer, project selector, visible model, Paste/Copy, attachments, Run/Stop, search and an actionable error. Record the actual Windows journey. |
| Host connections | Use the existing request-scoped Sites binding and a separately configured Windows adapter. Complete actual native GitHub/Drive reads and local MPC operations; retain their receipts. Follow `docs/HOST-CONNECTOR-INTEGRATION.md` at repository root. |
| Folder and transfer workflow | Index a selected folder in place; retain source/version and extraction lineage; preserve partial coverage. Pasted bytes, declared cloud origins and fresh native reads remain distinguishable. |
| Research and teaching | Explain the method's question, required inputs, assumptions, worked example, counterexample, actual result, limitation and primary reference. Let a user compare methods on the same evidence. |
| Numerical trust | Expose applicable exact comparisons without discarding the original receipt or implying universal solver coverage. Include the known disagreement in integrated UI/report acceptance. |
| Continuity | Reopen the selected project and report. Restore old receipts as history; obtain a current process handle only when a new native operation needs one. Respect retention in chat, source text, search indexes and backups. |
| Measured quality | Use a held-out corpus with independently reviewed expected results. Measure source/citation accuracy, missed issues, false findings, useful next actions, latency and reviewer effort against a fixed baseline. Split by project/source/time to limit leakage. |

The next valuable result is a completed project journey using those existing components: import evidence, ask a question, acquire a needed source, run an applicable calculation, inspect the source-bound result and any disagreement, save the report, then reopen and resume. After that works, measured improvements can justify broader model selection, additional methods, or learned ranking. The present evidence supports advanced prototype depth and specific integration work, without proving that MPC is best in every area.
